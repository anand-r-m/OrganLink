## Normalization facts (for Chapter 5)

- `organ_offer`: `run_id → organ_id` holds for every offer with a run; only `{offer_id}` is a
  whole-relation key; `(organ_id, recipient_id)` and `(run_id, rank)` are unique only under
  partial-index predicates. Consistency of the redundant `organ_id` is enforced by the composite FK.
- `match_result`: `distance_km → distance_score`; `{run_id, four component scores} → match_score`
  (via the run's stored weights); `exclusion_reason_id → qualified`. 0 counterexamples in data.
- `hla_allele`: `allele_name → locus` holds in data (0 violations), but only `(locus, allele_name)`
  is declared UNIQUE; `allele_name` alone is not declared unique.
